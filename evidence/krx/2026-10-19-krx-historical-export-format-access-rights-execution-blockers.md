**Review date:** 2026-10-19 KST. **Audit-only branch:** `indexalert-krx-pit-source-audit-20261013`. This is source-discovery evidence and does not attempt a KRX authenticated API call, scrape a KRX login, or deploy to the private worker.

## 1. Verified original-source discovery vs actual downloaded evidence

- Official [KRX Market Closing/Holiday lookup](https://open.krx.co.kr/contents/MKD/01/0110/01100305/MKD01100305.jsp): selects KRX separately from CME/EUREX and displays search/download UI plus columns `일자 / 요일 / 비고`. Public indexed text shows only the empty interactive grid; direct browser text fetch returned HTTP 403, not year-date rows. **Actual source files, binary SHA, rights and first-publication revisions have not been obtained**.
- A [2020 technical article revised 2022](https://hwangheek.github.io/2020/pandas-custom-businessday-from-krx/) documents a **historical, unauthenticated-looking legacy KRX file-download process**, using a GenerateOTP request with `name=fileDown`, `filetype=csv`, `url=MKD/01/0110/01100305/mkd01100305_01`, `search_bas_yy=<year>`, then a `file.krx.co.kr/download.jspx` POST. This is **third-party historical instructions**, not confirmation that endpoint access works, is approved now, or provides protected 2015–2026 official market data. No execution against that endpoint occurred.
- A [2017-07-16 contemporary FinanceData page](https://financedata.github.io/posts/pandas-market-days-krx.html) separately says the KRX yearly page supplied a downloaded **`.xls` Excel file** renamed `hdays-2017-KRX.xls`, shared via [a GitHub gist](https://gist.github.com/FinanceData/e09b8a5d720f3e7d89818fa1bfca4f5f). The page shows the **16 closure days visible as of July 2017** (before the Oct 2 government holiday change). This is a **third-party redistribution of a claimed original KRX export**, not independent KRX proof. Gist raw GET and redirect were inaccessible through the current reader, and no original binary was obtained or SHA-verified. Do not claim original bytes exist in Railway or in GitHub on this basis.
- **Format blocker:** the audit-only [private year runner](../../research_v1_krx_private_calendar_year_runner.py) deliberately reads only an exact-row-validated CSV or limited XLSX. It **rejects legacy binary XLS/OLE and HTML pretending to be XLS**. Even if the 2017 third-party `.xls` mirror became accessible, that would not authorize converting to CSV and pretending the conversion is the original. A separately reviewed deterministic legacy-XLS source-row verifier with independent original binary SHA and archival publishing context would be needed, if that is the actual authorized official export type.

## 2. Prevent an attractive but invalid substitute

The official [public-data record for the Financial Services Commission's KRX-linked **index price** API](https://www.data.go.kr/data/15094807/openapi.do) explicitly states records only from **2020-01-01**, daily data typically released after the next business day, a **Korea Open Government License Type 4** noncommercial/no-derivatives restriction, and restrictions on third-party redistribution; it directs commercial purchase inquiries to KRX Data Marketplace. This page describes a **different index price API**, **not** the KRX holiday-calendar download or the approved KRX KOSPI stock-history OpenAPI. Its licensing language **must not be blindly applied** to those different products, but it is strong evidence that a public-data API being technically open does not automatically grant future commercial Tiny Live trading-data use or original-data redistribution. Do **not** substitute it for 2015–2019 historical holidays or assume its 2020+ dates establish cash-equity market-open status.

Original user-approved private source collection was `PRIVATE_NONCOMMERCIAL_2015_2026`. A future real-money implementation must separately establish its product-specific license/usage terms with the original market data owner; do not infer that research permission extends to commercial automated trading.
