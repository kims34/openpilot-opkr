# Protected account intake — offline diagnostics only

The existing realtime00 normalizer requires field9201 but cannot check equality against a protected configured account. This intake requires exact raw-account equality before normalizing or persisting any receipt. Account mismatch, missing/non-string account, unknown raw-field extras, declared-day mismatch, or binding/journal fingerprint mismatch quarantine claims without retaining the raw delivery. Default representation and error messages redact the protected context.

`ProtectedAccountBinding` derives a deterministic domain-separated HMAC-SHA256 fingerprint using an independently injected fingerprint key of at least32bytes. The fingerprint uses the existing sha256:<64hex> format; the scheme is explicitly HMAC_SHA256_ACCOUNT_V1. It is a local keyed identity convention, not broker attestation. The key is not retained in this object, and the immutable process-local context prevents accidental account/fingerprint reassignment. This adds no broker credentials or platform variables and reads no environment/secret values. Configure future protected material only through a secret manager, never ChatGPT, repository, artifacts or logs. Use a dedicated fingerprint key separate from broker App Secret; never commit a real key or account.

No existing journal fingerprint is silently rewritten. A rotated key/different account requires an explicitly separate journal scope; attaching it to an existing scope fails closed. Raw source artifacts are NOT retained by this intake: recognized unused official fields are discarded before normalization and local hashing; only the exact account-free normalized row enters the existing append-only private inbox. Required private broker order/execution fields remain in the diagnostic DB; public reports contain no identifiers.

An exact comparison does not prove that the event came from a real account or authenticated broker connection: the protected account and raw event remain caller-supplied offline inputs. The source date is still externally declared, native-side numeric code is still externally bound, fees/tax remain unsettled and environment/source/real-account provenance admission remain false. No metadata boolean, HMAC or hash changes frozen admission. No network, login/token, account discovery/query, order/cancel/real request, funds movement or production deployment.
