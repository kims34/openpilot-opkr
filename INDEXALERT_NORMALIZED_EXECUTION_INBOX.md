# Private normalized execution inbox — offline diagnostics

Incoming normalized realtime00 records are committed before execution processing. Receipt payloads and arrival sequence, alternate conflicting deliveries, and processing attempts are append-only SQLite records with UPDATE/DELETE triggers. Only the exact normalized scalar field set is accepted; raw-account extras, REST aggregates and self-authority flags are rejected. Private account fingerprint/order/event fields remain in the diagnostic DB; counts-only reports and errors do not emit them. The digest is a normalized local identity aid, never raw-artifact or source provenance.

New receipts immediately stop SHADOW, block reconciliation and invalidate prior settlement bindings. Pending receipts or any conflicting delivery also block enable/reset/claims and zero-fill capital release even if a caller supplies a matching order snapshot. There is no automatic discard, override, conflict winner, retry submission, broker request or conflict-resolution authority. Conflicted/invalid normalized input can leave diagnostics blocked; independent resolution is intentionally not implemented.

Replay uses the existing native-ID/unit-quantity/price bridge. Default replay follows arrival order; a gap stays persisted and blocked. A caller may explicitly replay the known missing-first receipt, then replay the earlier arrival. This records quantities while preserving uncertainty until a newer complete matched batch; it does not authenticate source/order/date semantics or clear a gate automatically.

Bridge execution commit and processing-attempt marker are separate transactions by design. A crash after fill commit before its marker leaves a pending receipt; replay yields the existing native execution exactly once and records DUPLICATE. Receipt retention and native bridge idempotency provide crash recovery; this is not a claim of an atomic fill/attempt marker commit. Native identity, execution quantity and any late-fill principal restoration remain atomic inside the bridge.

Validation:145 offline tests (14 new inbox tests). Covers reconnect/persist-before-apply, same/different delivery duplicate IDs, gap recovery, retained conflicts, batch bypass prevention, append-only records, forbidden fields/authority, marker-crash window, pending/conflicted fill capital-release bypass prevention, sanitized errors and reports. Production Railway sender/runtime unchanged; frozen strategy/holdout/source contracts unchanged.
